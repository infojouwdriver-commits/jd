# JOUW DRIVER 2.0.0-rc.1

هذا إصدار مرشح للإطلاق، وليس إثباتاً لنشر إنتاجي أو تطبيقات موقعة.

## التغييرات

- واجهة إدارة موحدة ومتجاوبة مع اتجاه اللغة، ومراجعة صلاحيات الصفحات والتنقل وتجديد الجلسات لمنع حلقات إعادة التوجيه.
- إنشاء وتحديث وتعطيل حساب السائق بصورة ذرية في PostgreSQL، مع حفظ تاريخ الرحلات وإبطال الجلسات.
- عدم قبول كلمة مرور قديمة من جدول الاعتمادات بعد تعديل كلمة مرور المستخدم.
- قيود إضافية للعلاقات وعزل بيانات الشركات. البيانات التاريخية تحتاج تدقيقاً خاصاً قبل اعتماد القيود؛ لا توجد بيانات عملاء في هذا الإصدار.
- فاتورة رحلة محفوظة ذرّياً قبل توليد PDF، وإعادة استخدام الفاتورة عند تكرار الطلب، ونص عربي بخط DejaVu المرخص. إزالة روابط المشاركة غير المتاحة وخدمة QR الخارجية.
- تصحيح مرجع الدفع البلجيكي وفق Febelfin XML Credit Transfer Initiation v3.0، قسم 2.126 (باقي modulo 97؛ الصفر يصبح 97).
- فصل اكتمال رحلة العمل عن فشل إرسال Chiron، والاحتفاظ بمعرّف الرحلة الأصلي عند إعادة الإرسال. الإرسال الخارجي يبقى خلف مفتاح تشغيل صريح.
- سجل GPS أصلي مشفر في Android/iOS، وإعادة تشغيل النقاط المتأخرة قبل إنهاء العداد، وعدم محوها قبل تأكيد الخادم.
- مسار Actions لفحص الإصدار ثم صورة GHCR ثابتة بالـdigest، ونشر SSH ببيئة محمية، وفحص إعدادات، ونسخة مشفرة قبل الترحيل.

## تحقق محلي

| الفحص | النتيجة |
| --- | --- |
| اختبارات الوحدة وPostgreSQL المعزول والهاتف والنشر | 59 ناجحاً، 0 فشل، 1 متجاوز مشروط؛ 60 إجمالاً |
| HTTP security | 9/9 |
| الدخول والصلاحيات عبر معالجات Next الإنتاجية مع PostgREST محاكى | 17/17 |
| TypeScript | ناجح |
| بناء Next للإنتاج | ناجح؛ توجد تحذيرات غير مانعة |
| فحص المستودع للأسرار والبيانات | ناجح |
| PDF ببيانات اصطناعية ونص عربي | تم توليده ورسمه وفحصه بصرياً |

تحقق PostgreSQL المحلي يستعمل PGlite. فحص الحاويات الأصلية والنسخ والاستعادة موجود في Actions ولا يُستبدل بنتيجة PGlite. نتائج CI تخص commit المعني، لا أي تعديلات لاحقة. توجد تحذيرات React hooks وصور غير محسنة تحتاج متابعة، وليست نتيجة فحص خالية من التحذيرات.

## متطلبات اعتماد الإنتاج

1. خادم Linux وDNS وأسرار التشغيل وبيئات GitHub المحمية؛ GitHub لا يستضيف PostgreSQL أو هذا الخادم عبر Pages.
2. مراجعة البيانات التاريخية، استعادة معزولة للنسخ، واعتماد المخطط والصلاحيات على قاعدة الشركة الفعلية.
3. قبول Chiron الفعلي بمفاتيح الشركة وبيئة الاختبار قبل تمكين الإنتاج؛ نجاح الاختبارات المحلية لا يثبت قبول مزود الخدمة.
4. بناء Android/iOS وتوقيع APK/AAB/TestFlight بحسابات الشركة، واختبار الشاشة المقفلة وWaze وانقطاع الشبكة والطاقة وتبديل السائق على أجهزة حقيقية.
5. لم يُنفّذ استئناف تلقائي مضمون بعد قتل نظام الهاتف للعملية. لا يُسوّق العداد كقياس خلفي موثوق قبل إثبات اختبار الأجهزة ومعالجة هذا القيد.
6. لم يُنفّذ فحص نقر تفاعلي في متصفح فعلي لهذه النسخة؛ اختبارات التنقل البرمجية لا تعادل قبول UX على أجهزة العملاء.

المصدر وخطة النشر في المستودع، ودليل العمليات في `docs/OPERATIONS_AR.md`، ودليل تسليم الهاتف في `mobile/README_AR.md`.
