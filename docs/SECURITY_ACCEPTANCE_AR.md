# قبول الأمان قبل الإنتاج

هذه النسخة مرشحة للاختبار، وليست شهادة امتثال GDPR أو اعتماد عداد رسمي. قواعد ملكية السجلات تنفذ في الخادم؛ حساب قاعدة البيانات الخاص بالخادم واسع داخل مخطط التطبيق، ولذلك إتاحة PostgREST للإنترنت أو إعادة استخدام رمزه في الهاتف غير مسموح في تصميم النشر.

## ما يختبر تلقائياً

ملف `.github/workflows/ci.yml` يستبدل إعداد Deno القديم لأن المشروع Next.js وNode.js. يعمل بصلاحية قراءة المستودع، دون أسرار الإنتاج، ودون نشر أو شراء خدمة، ويثبت pnpm بالإصدار المحدد مع lockfile. عمليات GitHub الخارجية مثبتة بمعرف commit كامل تم التحقق منه من مستودعاتها الرسمية.

- فحص TypeScript وبناء إنتاج Next.js.
- اختبارات سياسة الأصل، قوائم الوصول، ملكية السجل، حجب التكاملات غير المعتمدة، منع وجهات Chiron غير المسموح بها، وتشفير الأسرار.
- اختبارات TOTP بمتجهات RFC 6238.
- اختبارات HTTP لحجب الوصول المجهول، الأصل المهاجم، نوع المحتوى غير الصحيح، endpoints المعطلة، وCSP nonce.
- تطبيق migrations على PostgreSQL WASM (PGlite) للتحقق من منع تكرار حفظ الرحلات، فرض صاحب الرحلة من الخادم، إلغاء صلاحيات دور المتصفح، منع إعادة استعمال OTP، وحدود محاولات قاعدة البيانات.
- اختبارات دخول على خادم Next.js الإنتاجي الحقيقي مع PostgREST محاكى محلياً: MFA وإعادة استخدام الرمز، تجديد الجلسة وحفظ MFA، ملفات ارتباط Secure/HttpOnly، رفض تعديل رحلة سائق آخر، الحساب المعطل، وإغلاق الوصول عند تعطل خدمة تحديد المعدل. هذه تختبر التطبيق؛ لا تستبدل اختبار PostgREST فعلياً.
- فحص ملفات المستودع لأشكال المفاتيح الخاصة وبعض رموز الخدمات ولأسماء تصدير قاعدة البيانات. هو حاجز إضافي محدود وليس ضماناً أن كل سر ممكن قد اكتشف.

## الحواجز الملزمة قبل استخدام بيانات حقيقية

| المجال | دليل القبول المطلوب |
|---|---|
| PostgreSQL | مراجعة schema المستنتج مقابل Zoer أو مخطط موثق من المالك، مطابقة عدد الصفوف والعلاقات ومراجعة السجلات اليتيمة، دون حذف تلقائي |
| PostgREST | تشغيل الصور المثبتة فعلياً والتحقق من JWT audience، RLS، رفض دور المتصفح، ومنع وصول الإنترنت المباشر للمنفذ |
| الأسرار | إنشاء قيم جديدة خارج Git، تشفير أسرار Chiron، واستخدام إعداد MFA خاص لكل مدير؛ تدوير أي سر سابق ظهر في ملف أو محادثة |
| الاستعادة | نسخة age مشفرة ثم استعادة عملية على قاعدة منفصلة والتحقق من عدد السجلات قبل الإنتاج |
| Chiron | يبقى `CHIRON_TRANSMISSION_ENABLED=false` حتى قبول عملي على بيئة Vlaanderen التجريبية للتنسيق والحقول والتكرار والفشل وإعادة الإرسال |
| الهاتف | اختبار GPS مع القفل وWaze، صلاحيات الموقع، البطارية، انقطاع الشبكة، إعادة تشغيل التطبيق، ووقت الرحلة الأصلي على أجهزة iOS وAndroid حقيقية |
| البيانات | ضبط مدد الاحتفاظ، جهة الاتصال ومسؤول المعالجة، سياسة الخصوصية والعقود مع المعالجين ومواقع التخزين والمراجعة القانونية المناسبة |
| الوظائف | اختبار الفواتير وPDF والعداد والتسعير وتغيير السيارة وحسابات الشركات متعددة المستأجرين؛ اجتياز CI لا يثبت هذه الوظائف كاملة |

## ضوابط التشغيل

1. استخدم `deploy/.env.example` فقط كقالب؛ لا ترفع `.env` أو backup أو export أو مفاتيح توقيع التطبيقات إلى GitHub.
2. تهيئة MFA تتم بواسطة `scripts/enroll-admin-mfa.mjs` إلى ملف خاص بصلاحية 0600. الدخول البديل بالشركة أو الهاتف يرفض حسابات مدير المنصة حتى لا تصبح مساراً يتجاوز MFA.
3. تحقق من `preflight` و`database-readiness` قبل التشغيل. إعداد schema المستنتج لا يصبح موثقاً تلقائياً بمجرد اجتياز الاختبارات.
4. اجعل Caddy بوابة الوصول الوحيدة واضبط `TRUST_PROXY=true` فقط في هذه البنية التي تستبدل ترويسات عنوان العميل.
5. الإرسال الخارجي للفواتير وروابطها العامة وبعض التكاملات القديمة معطلة. مراجعة PDF ومراجع QR الخارجية مطلوبة قبل مشاركة وثائق مع العملاء.

لم يتم في هذه البيئة اعتماد Chiron أو توقيع تطبيق متجر أو إجراء استعادة Docker فعلية. لا تعتبر النسخة جاهزة لنقل بيانات الإنتاج حتى إكمال الأدلة أعلاه.
