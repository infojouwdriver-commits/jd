# تعديلات الموقع: الصلاحيات والموافقات والفواتير

حالة العمل: نُفذت واختُبرت محليًا على الفرع `fix/web-approvals-billing-20261018`، انطلاقًا من `486953d`. لم تُرفع إلى المستودع البعيد ولم تُنشر، ولم تُطبّق على بيانات الإنتاج. لا تغييرات على تطبيق السائق أو إصدار جديد له.

## السلوك الجاهز للمراجعة

- صاحب الشركة يحتفظ بعرض بياناته وحساباته وموظفيه. إضافة أو تعديل أو إيقاف سائق/مركبة، وإضافة الموظفين أو تعديل صلاحياتهم، تُرسل للموافقة. لا يُنشأ حساب نشط ولا يتغير السجل قبل المراجعة.
- مسؤول الأسطول يطلب تغييرات الأسطول ضمن شركته؛ لا يصل إلى إعدادات الفواتير أو إدارة الموظفين.
- المحاسب يقرأ فواتير شركته وكشفها، دون تعديل الأسطول أو تسجيل الدفعات أو منح الصلاحيات.
- الإدارة تراجع الطلبات من «طلبات الموافقة ← طلبات الشركات». القرار والتنفيذ في معاملة واحدة، مع منع إعادة التنفيذ، والتحقق من ملكية الشركة والصلاحية الحالية وتغيّر السجل. الإيقاف يحافظ على التاريخ ويمنع تنفيذه أثناء رحلة نشطة.
- بوابة الشركة تعرض حالة الطلب: بانتظار الإدارة، موافق عليه، أو مرفوض. كلمات المرور تُجزّأ على الخادم ولا تُعرض مع الطلبات.

## الفواتير والتجربة

- تعرض الفاتورة السعر قبل الضريبة، نسبة وقيمة TVA، الإجمالي، الرصيد وحالة السداد. تُعرض الدفعات بتاريخها ومرجعها وطريقتها.
- الضريبة الافتراضية 21%، قابلة للتعديل في «إعدادات الفواتير». تُستخدم لملفات فوترة جديدة؛ لا تعيد كتابة الضريبة المحفوظة في ملفات سابقة أو مستندات صادرة، ولا تغير ضريبة أجرة الرحلات.
- يمكن للإدارة تسجيل دفعة نقدية أو تحويل بنكي، كاملة أو جزئية. تمنع إعادة المحاولة ازدواج الدفعة، ويُرفض الدفع الذي يتجاوز المستحق. طريقة الدفعات التاريخية غير المصنفة تبقى «غير محددة».
- المستند المصنّف كتجربة يمكن إصداره محليًا، ثم تجربة تسديده نقدًا دون إعداد مزوّد دفع أو Peppol. يبقى بلا قيمة ضريبية، ولا ينشئ بريدًا ماليًا، ويُفصل عن الحسابات الفعلية.
- لا يوجد تجاوز لقواعد الإصدار الفعلي. إعداد وربط Peppol ومزوّد الدفع الإلكتروني خطوة لاحقة مستقلة.

## دليل التحقق

نجح بناء الإنتاج، وفحص الأنواع، وESLint للنطاق المعدّل، واختبارات الخادم والصلاحيات وقاعدة البيانات المعزولة. اختُبرت الواجهة بالعربية والفرنسية والهولندية بعرض 390 و1280 بكسل، مع فشل/إعادة محاولة، وإبقاء الطلب معلّقًا، وموافقة الإدارة، والإصدار التجريبي والسداد النقدي. نجحت أيضًا اختبارات واجهات العمليات السابقة.

النتائج التفصيلية في `tests/verification/web-approvals-billing-local.json` و`auth-integration.json`. فحص التصميم الثابت أبلغ عن سبع حالات معروفة في مكونات Radix المشتركة: يخلط Select المؤلف بالقائمة الأصلية، ويعتبر أزرار asChild بلا فعل. راجعت المصدر وشغّلت تفاعلاتها في المتصفح؛ لا أدّعي نجاح ذلك الفحص الثابت أو تدقيق كامل لكل الشاشات القديمة. بقيت تحذيرات build سابقة في شاشات قديمة، ولم يُشغّل اختبار Docker/PostgreSQL الأصلي على هذا المضيف؛ اختبارات SQL هنا تستخدم PGlite ببيانات اصطناعية.

أُعيد بناء Graphify محليًا بالإصدار المثبت ودون نماذج أو مزامنة خارجية. نجح `python3 scripts/code-map.py --check`: تطابق 507 ملفات مصدر ومخرجات المرجع.
