# الفواتير والدفع عبر Stripe

السياسة المعتمدة في 26 أكتوبر 2026: العقد يحدد الالتزام السنوي، والفاتورة هي وحدة التحصيل. العرض يبقى 50€ شهريًا شامل TVA بنسبة 21%، اثنا عشر قسطًا فقط، دون تجديد. لا تُنشأ تفويضات خصم آلي جديدة. لا تُعدّل العقود الموقعة أو السجلات المالية السابقة.

## سير الاستخدام

- بعد توقيع عقد جديد مؤهل، يحفظ النظام جدول الأقساط المحلي. العامل الدوري يجهز الفاتورة المستحقة ثم يصدرها ويرسل PDF ورابط دفع Stripe إلى عنوان الفوترة الثابت في المستند. آخر قسط يوقف الجدول عند 12؛ لا يتغير تاريخ العقد.
- تُسجّل الشركات الجديدة منذ إنشائها بانتظار تفعيل الخدمة؛ توقيع العقد يربط هذا الانتظار بالقسط الأول، وسداد الشهر الأول يفعّلها. يمكن للمالك الدخول ومراجعة العقد والفواتير قبل السداد؛ بدء الرحلات والورديات الجديدة وإدارة الأسطول والموظفين يبقى محميًا حتى تسجيل السداد كاملًا. لا تُحجب الشركات التاريخية أو الرحلات الجارية بسبب ترحيل هذا التحديث أو تأخر قسط لاحق.
- في قسم الفواتير المستقلة، زر «إرسال الفاتورة» يصدر المسودة البريدية إن لزم ويرسل PDF ورابط الدفع. لا يلزم عقد أو اشتراك. العنوان والمبلغ وهوية الجهة المصدرة من النسخة المالية الثابتة، وليس من إدخال العميل في رابط الدفع.
- البريد يفتح رابطًا خاصًا بفاتورة واحدة ثم Stripe Checkout لدفع المبلغ المتبقي فقط. لا تُحفظ بطاقة لتفويض شهري ولا يُنشأ اشتراك Stripe أو فاتورة ضريبية ثانية. كل دفعة يتخذها العميل صراحةً.
- PDF يعرض QR محليًا للتحويل إلى حساب الجهة المصدرة المحفوظ في الفاتورة؛ Communication يطابق رقمها. اختر طريقة واحدة فقط. التحويل المباشر إلى حساب الشركة يحتاج مطابقة كشف البنك وتسجيل الاستلام؛ لا يؤكده مسح QR ولا إشعار Stripe.
- إرسال PDF بالبريد لا يثبت التبادل المنظم أو Peppol. `delivery_channel=email_pdf` منفصل عن إثبات `exchange_reference` الفعلي؛ المسار المنظم السابق يحتفظ بفحوصه. يجب متابعة متطلبات التبادل المنظم بشكل مستقل.

## التسوية وعدم التكرار

- الرابط HMAC خاص، محدود الصلاحية، في جزء fragment ولا يمنح جلسة حساب. فتح البريد/المعاينة أو مراجعة الرابط لا ينشئ Checkout أو سدادًا؛ العميل يضغط الدفع صراحةً. الصفحة تعرض الرقم والمبلغ فقط.
- Checkout واحد مفتوح لكل فاتورة، مع حجز محلي ثابت ومفتاح Stripe idempotency. المبلغ EUR من الرصيد المحاسبي، دون خصومات أو تحويل عملة أو إضافة ضريبة ثانية. مهلة الإنشاء المبهمة تتطلب مراجعة بدل إنشاء تحصيل آخر.
- إشعارات Stripe الموقعة تربط Session المحفوظة بالحجز المحلي، وتتحقق من البيئة والمبلغ والعملة وPaymentIntent والخصم الفعلي وحالته والردود والنزاعات قبل إنشاء الاستلام وتخصيصه في معاملة واحدة. العودة إلى الموقع ليست إثباتًا للدفع.
- `checkout.session.completed` غير المدفوع يبقى معلقًا؛ النجاح المتأخر يعتمد `checkout.session.async_payment_succeeded`. الفشل المتأخر يحرر المحاولة بعد إثباته. إعادة الحدث لا تكرر الدفع.
- قبل تسجيل تحويل بنكي أو نقد، ينهي الخادم Session المفتوحة لدى Stripe ويتحقق من انتهاء صلاحيتها. الدفع المكتمل أو الجاري أو المبهم يمنع السداد اليدوي حتى التسوية. الحارس داخل قاعدة البيانات يمنع سباقات التزامن.
- استلام متأخر يتعارض مع الرصيد يحفظ في سجل ثابت للمراجعة دون تخصيص ثانٍ، ويوقف روابط التحصيل المتنافسة. الردود والنزاعات تظهر للمراجعة؛ لا يصطنع النظام ردًا أو يحذف الاستلام السابق.
- الفواتير المسددة لا تعرض طلب تحويل جديد. العقود التي لها تسجيل تحصيل آلي قديم لا تحصل على Checkout منفصل أو QR بنكي حتى المراجعة. معالجة الاشتراكات السابقة والإشعارات الموقعة تبقى متاحة، وإنشاء تفويض جديد مغلق.

## الانتقال والتشغيل

الترحيل إضافي `20261026_invoice_checkout.sql`. لا ينقل فواتير تاريخية إلى الإرسال تلقائيًا. العقود الحالية غير المفوضة آليًا ترسل فقط المستندات الجديدة المجهزة بعد وقت الانتقال؛ المسودات الأقدم يرسلها المسؤول صراحةً. لا يعيد إنشاء الحساب البنكي أو الأسرار أو Sandbox.

المفتاح المقيد وWebhook يبقيان في إعداد الخادم الخاص؛ لا يصلان للبناء أو المتصفح أو المستودع أو السجلات. يستخدم الحساب الحالي وSDK 23.0.1 وAPI `2026-09-30.endive`. لا تغيير للحساب البنكي لدى Stripe. الضريبة الشاملة محددة من الفاتورة المحلية؛ `automatic_tax` غير مفعلة، ولا نضيف Stripe Tax أو ضريبة ثانية.

النشر يتطلب اختبارات قاعدة البيانات والتوقيعات والمتصفح، صورة محددة مقبولة، ونسخة مشفرة حديثة مختبرة الاستعادة. يُحفظ إصدار الرجوع وإعداد Stripe والبريد والبيانات السابقة. الاختبارات لا تخصم أموالًا حقيقية ولا ترسل فواتير أو عقودًا إلى عملاء حقيقيين.
