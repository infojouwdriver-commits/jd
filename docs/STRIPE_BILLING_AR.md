# تحصيل اشتراك JOUW DRIVER عبر Stripe

المصدر: العرض والعقد في `src/lib/subscription-offer.ts` و`20261018_contract_billing.sql`؛ 50€ شهريًا شامل 21%، اثنا عشر قسطًا، دون تجديد تلقائي. لا يستخدم هذا المسار Stripe Connect أو Stripe Tax المدفوع. الضريبة محددة يدويًا بنسبة 21% وشاملة ضمن 50€؛ يجب مراجعة المعالجة الضريبية قبل دعم عروض أو دول أخرى.

## سير العمل

- الشركة معتمدة، وصاحبها نشط، والعقد موقّع ومرتبط بالفوترة.
- صاحب الشركة وحده يفوض وسيلة الدفع في Stripe Checkout. الإدارة والمحاسب يقرآن الحالات ولا يفوضان الخصم بدل العميل.
- إشعار موقّع يؤكد نجاح SetupIntent؛ حفظ البطاقة ليس استلامًا للمال. ينشئ الخادم Subscription Schedule محدودًا بنهاية العقد، مع `end_behavior=cancel` وبدون احتساب نسبي. يثبت أول مستند Stripe لبدء التحصيل بعد التفويض.
- يبدأ الاشتراك الآلي في أول فترة من العقد فقط، دون دفعات أو إشعارات دائنة سابقة. يبدأ التحصيل عند التفويض ثم شهريًا حتى نهاية العقد؛ لا يُنقل تاريخ العقد أو يُعاد تحصيل تاريخ قديم. بدء العقود المتأخرة أو ترحيل اتفاقات سابقة يتطلب مراجعة مستقلة.
- `invoice.paid` يستدعي قراءة الفاتورة وInvoicePayment وPaymentIntent والخصم، ويتحقق من الشركة والسعر والعملات والمبلغ والضريبة وعدم الردّ أو النزاع. لا يعتمد التسجيل على رابط العودة أو البريد أو metadata وحدها.
- تحفظ الدفعة أولًا في سجل استلام مستقل. تطابق رقم القسط في الفاتورة المحلية عند إصدارها؛ لا تتحول فاتورة مجهزة إلى فاتورة قانونية صادرة بسبب الدفع، ولا يُدّعى إرسال Peppol.
- إصدار الفاتورة بعد الدفع يربطها بالاستلام مرة واحدة. تكرار الحدث أو وصول حدث قديم لا يكرر السداد أو يخفض الحالة الحديثة. المبالغ غير المتوقعة أو النزاعات تظهر للمراجعة دون اختلاق سداد أو رد مالي.
- تبقى الفوترة اليدوية متاحة للعقود الأخرى. يمنع تسجيل النقد أو الإشعارات الدائنة على عقد جرى تفويضه آليًا لتجنب التحصيل مرتين؛ العقود الملغاة التي لها مدفوعات أو محاولات معلقة تحتاج تسوية مستقلة قبل الانتقال اليدوي.
- فشل الدفع يظهر مع رابط فاتورة Stripe الآمن عندما يتوفر. لا يعطل النظام رحلات السائقين بسبب ذلك.

## الأسرار والنشر

المفتاح المقيد موجود باسم `STRIPE_SECRET_KEY` في أسرار بيئة GitHub `production`، ولا يُرسل للبناء أو للمتصفح أو لتطبيق السائق. لا تُحفظ قيم مفاتيح في المستودع.

يلزم وصول المفتاح إلى الحساب والأسعار والضريبة والفواتير وInvoicePayments وPaymentIntents والخصومات للقراءة، والعملاء وCheckout وSubscription Schedules والفواتير لإنشاء التفويض والتحصيل، وWebhook Endpoints لإنشاء الإشعار. لا حاجة إلى تحويل أموال أو تعديل الحساب البنكي.

بعد اختبارات قاعدة البيانات والمتصفح واختبار Stripe معزول وبناء الصورة الدقيقة والنسخ والاستعادة، يستخدم إجراء النشر المحمي ثم `configure-stripe.yml` للمصدر المختبر والمنشور. يتحقق المثبت من الحساب والسعر، ويجهز ضريبة شاملة 21% وإشعارًا موقّعًا بالإصدار `2026-09-30.endive`، ويحفظ سره في ملف خاص على الخادم، ويعيد إنشاء حاوية التطبيق فقط. لا يخصم من أي عميل أثناء الإعداد. يعيد إعداد التطبيق السابق إذا فشل التحقق، ويحافظ على سر الإشعار لاستكمال آمن.

لا يوصف الربط بأنه مفعّل قبل إتمام هذه الخطوات والتحقق الفعلي. لا تُستخدم أموال حقيقية للاختبار. المصادقة الناقصة أو انتهاء نافذة منع التكرار الخارجية (23 ساعة) يتطلبان مراجعة؛ لا يعيد الخادم إنشاء اشتراك أو عميل بصمت.
