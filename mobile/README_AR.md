# تطبيق السائق — أساس تجريبي قابل للبناء

هذه نسخة أولية من غلاف iOS وAndroid مرتبطة ببوابة السائق الحالية، وليست APK أو IPA جاهزة للنشر. لا توجد حسابات متجر أو مفاتيح توقيع أو سيرفرات مدفوعة ضمن الملفات.

## البنية

المشروع الأصلي Next.js يحتاج الخادم وواجهات API؛ لا يمكن تحويله إلى static export دون إعادة بناء كبيرة. الغلاف هنا يفتح نفس أصل HTTPS للبوابة، فتظل الجلسة داخل cookie آمنة وتظل أسرار PostgreSQL وChiron على الخادم. لا تضف مفاتيح API أو كلمات مرور إلى إعدادات الهاتف. يحتاج فتح البوابة من البداية إلى الإنترنت؛ `www/index.html` ليس نسخة كاملة تعمل دون اتصال. تشغيل رحلة بدأها السائق ثم انقطع اتصالها يختلف عن تشغيل التطبيق من الصفر بلا إنترنت.

الإصدارات مثبتة في `package-lock.json`: Capacitor 7.6.9 وإضافة background-geolocation 1.2.26 لأن الإضافة توثق دعم Capacitor 7. هذه نقطة بدء للتحقق، وليست تأكيداً للقبول في متاجر 2026. يجب مراجعة دعم Capacitor ومتطلبات target SDK وXcode الحالية قبل النشر. الترقية إلى Capacitor 8 تحتاج تحققاً مستقلاً من الإضافة وجسور Android؛ لا ترفع الإصدارات عشوائياً.

## الإعداد

1. انشر نسخة الخادم على أصل HTTPS موثوق يمكن للهاتف الوصول إليه مباشرة. رابط تجربة محمي بتسجيل الدخول الخارجي إلى ChatGPT ليس أساس توزيع للسائقين.
2. من مجلد `mobile` شغّل `npm ci`.
3. عيّن `MOBILE_APP_URL` إلى أصل الخادم الحقيقي، دون مسار أو كلمة مرور، مثلاً متغير بيئة جلسة العمل. أداة configure ترفض HTTP وlocalhost وIP وعناوين placeholder. لا يوجد عنوان إنتاج افتراضي.
4. Android: `npm run android:init` ثم من جذر المشروع `bash capacitor-build.sh debug`. يحتاج Android Studio وSDK وJDK المتوافقة مع إصدارات Capacitor المثبتة.
5. iOS: على macOS وXcode المتوافقين شغّل `npm run ios:init` ثم `bash capacitor-ios-build.sh`. أداة أذونات iOS تستخدم Python 3. افتح Xcode واختر Apple team واختبر هاتفاً حقيقياً قبل Archive.
6. احفظ مشاريع native الناتجة في Git بعد مراجعتها. لا تحفظ ملفات التوقيع أو local.properties أو بيانات الحساب. root scripts تستدعي CLI محلياً فقط ولا تثبت أدوات بصلاحيات sudo.

## الموقع وإيقاف التتبع

`useGeolocation.startWatching(callback, { background: true })` هو طلب تتبع خلفي عبر الإضافة الأصلية فقط أثناء رحلة نشطة. الاستخدام الافتراضي دون هذه الخيارات يطلب الموقع في المقدمة. إصدار المتصفح يستخدم browser GPS ولا يوفر ضمان تتبع خلفي.

- `stopWatching()` يوقف callbacks فوراً ثم يزيل native watcher حتى لو وصلت نتيجة التسجيل بعد طلب الإيقاف.
- يجب استدعاء `stopAllMobileLocationWatches()` عند تسجيل الخروج أو تبديل الحساب، بالإضافة إلى إيقاف مراقبة الرحلة عند نهايتها.
- قبل التتبع الخلفي على Android يطلب إذن الإشعار؛ إن رفضه السائق، لا يبدأ التتبع الخلفي بصمت.
- إضافة Android تستخدم foreground service مع إشعار ظاهر. إعداد `useLegacyBridge` مطلوب وفق دليل الإضافة لتفادي انقطاع callbacks بعد خمس دقائق.
- نصوص iOS توضّح استخدام الموقع أثناء الرحلة وعندما تكون الشاشة مقفلة. لا تضف تتبعاً خارج الرحلات.
- لا نستخدم `ACCESS_BACKGROUND_LOCATION` في التطبيق المضيف دون حاجة مثبتة؛ خدمة الموقع التي تبدأ حين يكون التطبيق ظاهراً تخضع أيضاً لأذونات Android الفعلية. راجع أذونات الإضافة المدمجة وسلوك إصدار الجهاز، ولا تتجاوز رفض المستخدم.
- طلب الموقع عند البداية ينتظر حتى 15 ثانية للحصول على قياس عمره لا يتجاوز 30 ثانية ودقته لا تتجاوز 50 متراً؛ لا يعيد موقعاً مخزناً عند الفشل.
- الموقع يحتفظ بوقت قياس GPS الأصلي، ولا يعيد تسمية موقع قديم على أنه جديد. المواقع المحاكية أو الإحداثيات غير الصالحة تُرفض في native adapter.

## حدود مهمة قبل الاعتماد المهني

يتضمن الإصدار الآن fork محلياً للإضافة في `plugins/background-geolocation`: تحفظ الخدمة الأصلية نقاط الرحلة قبل إرسالها إلى WebView. تستخدم Android AES-GCM ومفتاح Android Keystore، وiOS CryptoKit AES-GCM ومفتاح Keychain خاصاً بالجهاز. يرتبط التشفير بمعرّف السائق ومعرّف الرحلة، ويُستثنى السجل من النسخ الاحتياطي. تستعيد البوابة السجل على دفعات محدودة عند بدء المراقبة واستئناف الشاشة، وتمنع تكرار الطوابع الزمنية وتؤخر النقاط الحية حتى انتهاء الاستعادة. الخطأ أو السجل الممزق لا يُعامل كنجاح.

هذا لا يضمن التتبع بعد قتل العملية: Android يوقف المراقبين عند فك ارتباط النشاط بالخدمة، وiOS لا يضيف استعادة تلقائية لجلسة Core Location بعد إنهاء العملية. يمكن استعادة النقاط التي حُفظت بالفعل، لكن لا يمكن استعادة قياسات لم تُجمع. تُمسح نقاط الرحلة الأصلية فقط بعد إقرار الخادم باستلام الرحلة، وليس عند تسجيل الخروج؛ فشل التنظيف يُبقي الحمولة المحلية لإعادة محاولة العملية بمفتاح منع التكرار نفسه. يجب احتساب أثر صلاحية الجلسة وانتهاء تسجيل الدخول أثناء رحلة دون إنترنت.

اختبارات Node تتحقق من الترتيب والتقسيم ومنع التكرار والإيقاف ومدخلات الموقع، وليست بديلاً عن بناء native. لم تُجمع Java/Kotlin أو Swift ولم تُوقّع APK/AAB/IPA في بيئة هذا الإصدار: Android SDK/Gradle وmacOS/Xcode غير متاحة هنا. لذلك لا تعلن النسخة عداداً مضموناً في الخلفية، ولا تعتمدها للحساب الفعلي قبل بناء النظامين واختبارات القبول أدناه.

إغلاق التطبيق بالقوة أو إيقاف خدمة الموقع من النظام قد يوقف التتبع. تشغيل تطبيق SSR من الصفر بلا إنترنت غير متاح. إصدارات release/AAB الناتجة لا تُعتبر موقعة أو منشورة؛ إعداد signing ومراجعة الخصوصية والإفصاحات في المتجر خطوات منفصلة. هذا الغلاف يحمّل كود الويب عن بعد؛ أي اختراق للخادم يصبح خطراً على جسر native، لذلك يجب حصر التنقل إلى أصل موثوق، إبقاء CSP وحماية XSS، ومراجعة تحديثات الخادم بعناية. استخدام remote server configuration هنا أساس اختبار يجب مراجعة ملاءمته لسياسات المتاجر، وليس ضمان قبول.

## اختبار قبول على أجهزة حقيقية

- رحلة 30 دقيقة والشاشة مقفلة، ثم رحلة مع Waze في المقدمة؛ قارن عدد النقاط والطوابع الزمنية والمسافة مع سجل مستقل.
- قطع الإنترنت ثم استعادته، إغلاق الشاشة، توفير البطارية، واستعادة التطبيق بعد إيقاف النظام له.
- رفض GPS ورفض الإشعار وموقع تقريبي فقط؛ يجب أن تُعرض مشكلة القياس ولا يُسجّل نجاح وهمي.
- إنهاء الرحلة وتسجيل الخروج ثم تأكد أن إشعار الخدمة يختفي وأنه لا توجد نقاط موقع لاحقة.
- إعادة تسجيل الدخول بسائق آخر دون خلط السجل المحلي.
- تحقق من تسجيل الدخول وrefresh وCSRF عبر HTTPS الحقيقي داخل WebView على النظامين.
- تحقق من safe area ولوحة المفاتيح، فتح الفواتير ومشاركتها، وروابط خارجية، ووصول ذوي الإعاقة.
